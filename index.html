04 / Data decisions

I kept information honest.

I checked missing values and duplicates instead of deleting data automatically.

53,580

missing cells in the final dataset

Many are structural: some fields did not exist in earlier MYH workbooks.

My decision: keep missing values as missing. A blank value is not the same as zero.

Checks I completed

✓0 exact duplicate records.
✓0 missing application IDs.
✓0 repeated IDs within the same year.
✓All 7,641 rows kept.

I also preserved programme-name variations because similar titles do not necessarily mean duplicate applications.

06 / Machine-learning perspective

What could a model predict?

I identified a possible target and checked which columns could cause target leakage.

Possible target: Beslut

Application decision

Approved · Beviljad2,613
Rejected · Ej beviljad5,027
Withdrawn · Återkallad1

The withdrawn record stays in the dataset, but a future binary classifier would need to handle it separately.

Avoiding target leakage

When predicting a decision, I should not give the model fields that already describe the outcome.

✓I identified and excluded 9 columns from a preliminary list of model inputs.
✓24 candidate input columns remain for further evaluation.
I did not remove these columns from the exported dataset or train a model.

10 / Reflection & next steps

What I learned

Preparing useful data takes more than joining files together.

Understand first

I learned to inspect source files and verify column meanings before combining different years.

Make careful decisions

I learned why missing values, duplicate checks and target leakage matter for data quality.

Check AI suggestions

I used ChatGPT to understand pandas and Streamlit, then checked the code and results myself.

My result

A documented, reproducible preparation process; a cleaned dataset covering 2020–2025; and a Streamlit explorer. Further preparation would be needed before training an ML model.
